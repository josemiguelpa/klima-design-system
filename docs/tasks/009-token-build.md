# TASK-009: Generar artefactos CSS y TypeScript

## Objetivo

Transformar los tokens DTCG en outputs deterministas consumibles.

## Dependencias

- TASK-008.

## Alcance

- Generar CSS custom properties con prefijo `--klima-`.
- Generar valores y tipos TypeScript.
- Definir exports públicos.
- Marcar outputs como generados.
- Añadir test que falle si outputs están desactualizados.

## Fuera de alcance

- Tema Solé completo y shadcn.

## Criterios de aceptación

- Dos builds consecutivos producen bytes idénticos.
- Todos los export targets existen después del build.
- Una fixture importa CSS y TypeScript desde el paquete empaquetado.

## Decisiones del propietario

- Exports públicos:
  - `@klima-ds/tokens`: valores y tipos sin dependencias de Node.
  - `@klima-ds/tokens/css`: hoja de custom properties.
  - `@klima-ds/tokens/tooling`: validador, ensamblador, contraste y generador; usa `node:fs`.
- Valores TypeScript en dos formas: `tokens` anidado con referencias `var(--klima-…)`, que siguen el modo activo, y `values.<modo>` plano con el valor CSS resuelto.
- Los artefactos generados no se versionan. `prepack` reconstruye el paquete y verifica que `dist/` coincida con las fuentes.

## Implementación

### Build

`node scripts/build.mjs` limpia `dist/`, compila el tooling con `tsc` y escribe los artefactos que devuelve `generateArtifacts()` (`src/generate.ts`). No usa shell, así que funciona en Linux, macOS y Windows.

| Archivo en `dist/` | Export                     | Contenido                                                              |
| ------------------ | -------------------------- | ---------------------------------------------------------------------- |
| `tokens.css`       | `@klima-ds/tokens/css`     | Custom properties `--klima-*`                                          |
| `tokens.css.d.ts`  | tipos de `./css`           | `export {}` para `noUncheckedSideEffectImports`                        |
| `index.js`         | `@klima-ds/tokens`         | `modes`, `defaultMode`, `cssVariables`, `tokens` y `values`            |
| `index.d.ts`       | tipos de `.`               | `Mode`, `TokenPath` (unión literal) y constantes con tipos literales   |
| `tooling.js`       | `@klima-ds/tokens/tooling` | API de TASK-005 y TASK-008, más `generateArtifacts` y `checkGenerated` |

Todos los artefactos generados empiezan con el aviso `Generated by @klima-ds/tokens … Do not edit`.

### CSS

- `:root, [data-theme="light"]` declara todos los tokens del modo por defecto: primitivas globales y de marca, semánticos y componentes.
- `[data-theme="dark"]` solo redeclara los tokens cuyo valor CSS cambia.
- Los aliases se emiten como `var(--klima-<ruta>)`, así los tokens de componente siguen el modo sin repetirse. Un `$ref` a un `$value` completo también se emite como `var()`; un `$ref` a un descendiente se emite como literal.
- La ruta `a.b.c` se convierte en `--klima-a-b-c`. Si dos rutas producen el mismo nombre, el build falla.
- Serialización:
  - `color` sRGB → hex en minúsculas (`#rrggbb`, o `#rrggbbaa` si hay alfa);
  - espacios de `color()` → `color(<espacio> …)`;
  - `dimension` → `<valor><unidad>`;
  - `fontWeight` → número, incluidos los nombres DTCG;
  - `fontFamily` → lista entrecomillada, salvo familias genéricas;
  - `number` → número, y la opacidad se divide entre 100;
  - `shadow` → valor de `box-shadow`.
- `typography` y espacios de color sin función CSS hacen fallar el build de forma explícita.
- No declara `data-brand`, `body`, `*`, scrollbar ni reset. La selección de marca corresponde a TASK-010.

### Paquete

- `sideEffects: ["*.css"]` evita que los bundlers eliminen `import "@klima-ds/tokens/css"`.
- `prepack` ejecuta `build` y después `check-generated`. Un tarball no puede salir con artefactos desactualizados ni editados a mano.

## Verificación

- `packages/tokens/src/__tests__/generate.test.ts`:
  - dos generaciones producen bytes idénticos;
  - todos los artefactos llevan el aviso de generado;
  - todas las custom properties usan el prefijo `--klima-`;
  - `:root` declara todos los tokens y dark solo los que cambian;
  - los aliases se emiten como `var()` y no hay selectores globales;
  - la serialización de cada tipo y los errores ante tipos y espacios de color sin salida CSS;
  - colisiones de nombres, fuentes inválidas y `$ref`;
  - `checkGenerated` detecta archivos desactualizados y ausentes.
- `fixtures/tokens/test/packed-package.test.js` consume el tarball real: ejecuta `pnpm pack` dos veces, cada vez con `prepack`, y lo extrae en una aplicación temporal. Comprueba:
  - las dos builds son idénticas byte a byte;
  - todos los targets de `exports`, `main` y `types` existen;
  - Node importa `.` y `./tooling` y resuelve `./css`;
  - un consumidor TypeScript estricto compila con `noUncheckedSideEffectImports`, y `@ts-expect-error` cubre rutas y modos inválidos;
  - Vite empaqueta el CSS y los valores.
- `pnpm verify:manifests`: publint y attw (`esm-only`) en verde para `.`, `./css` y `./tooling`.
